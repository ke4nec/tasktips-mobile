# TaskTips Android 首版功能设计

> 状态：功能设计基线，尚未实现。本文区分已确定的首版行为与第 6 节的待确认事项。

## 1. 定位与范围

移动端定位为：**随手记录、聚焦今日任务、与桌面端接续编辑的本地优先待办工具**。

桌面端已有的核心能力包括 Markdown 编辑、日期与优先级、搜索筛选、三级目录、标签、回收站和同步。Android 保留这些数据能力，将托盘、独立便签窗口和右键菜单转换为底部导航、全屏编辑和底部操作面板。

本次确定的首版范围：

- 核心待办功能＋服务端同步。
- 增加 Android 文字、链接分享入口。
- Markdown 采用“编辑／预览切换”。
- 按实际 [v0.3 设计稿](../design/android-mobile-ui.html)布局，补齐分类页新建 Todo FAB、多设备列表、上传下载日志。
- 桌面小组件、通知提醒、重复任务、日历、批量管理、拖拽排序和云盘目录同步放到后续。

设计稿负责视觉与页面布局，本文补充业务行为；文件格式、分类生命周期和同步语义分别以桌面端设计、[分类设计](../../tasktips/docs/todo-classification-design.md)和[服务端同步设计](../../tasktips/docs/tasktips-server-sync-design.md)为准，HTTP 字段以 OpenAPI 为准。HTML 中的演示 ID、静态日期、固定数量和状态切换按钮不进入正式产品。发现跨仓库文档与代码不一致时记录差异并验证，不在移动端另创协议。

## 2. 页面与功能

底部四个入口保持为：**今日、列表、分类、设置**。编辑、回收站和同步使用二级页面，隐藏底部导航并保留返回按钮。

| 页面 | 首版功能与交互 |
|---|---|
| **今日** | 显示“已过期”和“今天到期”两组未完成任务，过期在前；一键完成、进入详情、搜索、跳转即将到期列表。完成后立即移出今日。 |
| **Todo 列表** | 默认显示全部未完成任务；可切换全部、即将到期、已完成。搜索标题、正文纯文本和标签；底部面板提供日期、优先级、目录、标签筛选及排序。 |
| **Todo 编辑** | 正文编辑／预览切换、自动保存；设置优先级、截止日期、单个目录和多个标签；支持完成、取消完成、移入回收站。格式工具栏随键盘上移。 |
| **目录与标签** | 分段切换；目录支持最多三级、新建、重命名、调整父目录、颜色和删除；标签支持新建、重命名、颜色和删除。点分类进入筛选后的 Todo 列表。保留既有标签分组展示。 |
| **回收站** | 在现有布局内补充 Todo／目录／标签类型筛选；显示删除时间、剩余保留天数，支持恢复、彻底删除、清空。永久删除和清空必须确认。 |
| **同步** | 配置服务端、登录、选择或创建项目；立即同步、自动同步开关、离线与错误状态、冲突处理、多设备信息和本机同步日志。 |
| **设置** | 系统／浅色／深色主题；同步、回收站、本地存储说明与占用、版本信息。 |
| **首次启动** | 简短介绍本地保存和离线使用；无需登录即可开始，之后从设置连接同步。 |

交互补充：

- 今日、列表、分类页显示新建 Todo FAB；分类页另外保留“新建目录／标签”按钮。
- 从今日新建预填今天截止；普通列表新建不预填日期；从分类列表新建继承当前目录或标签。
- 返回列表时恢复筛选与滚动位置。
- 系统返回与页面返回行为一致：先关闭当前弹层或键盘，再退出编辑页；退出前刷新本机保存。保存失败时停留在编辑页并提供重试，不能丢弃正文后返回。
- 完成、取消完成、修改元数据和移入回收站均走统一写入流程；失败时恢复原显示状态。移入回收站也需确认，确认文案显示当前 Todo 标题。
- 空列表、无搜索结果、保存失败、同步失败分别提供对应提示和操作。
- 中文界面、系统主题默认值、48dp 最小触控区域、大字体、TalkBack、安全区域和减少动画均纳入验收。

## 3. 核心功能规则

**待办与视图**

- “收件箱”语义沿用桌面端：全部未完成任务；“未分类”通过目录筛选表达。
- 今日为未完成且 `dueDate <= 本地今天`；即将到期为未完成且日期在今天之后。截止日期不触发通知。
- 优先级保持 `0/1/2/3`，对应无、低、中、高。
- 默认排序为未完成在前、过期在前、优先级降序、截止日期升序、更新时间降序；截止日期升序时无日期排在最后。列表支持更新时间、创建时间、截止日期、优先级、标题排序及升降序。清除筛选同时恢复默认排序。
- 已同步的 Inbox／All 自定义顺序继续读取和保留，首版不提供手机拖拽修改入口。
- 多标签默认全部匹配；复杂标签组合和批量操作后续增加。
- 搜索大小写不敏感，默认排除回收站；目录筛选包含子目录。各维度之间取交集，优先级多选取并集；搜索和筛选不改写同步索引中的排序。
- 日期使用无时区的 `YYYY-MM-DD`；跨过本地午夜、切换时区或恢复前台时重新计算今日分组，不修改用户的截止日期。

**编辑与保存**

- 不设置独立标题输入框；标题取正文首个非空行，剥离 Markdown 标记并限制为 80 字符。空标题仅在界面显示“未命名 Todo”。
- 标题派生复用桌面端的兼容样例：跳过只有 Markdown 标记的行，按 Unicode 码点计数，超长标题取前 79 个码点加省略号；避免直接按 Dart UTF-16 下标截断 emoji。
- 支持标题、强调、列表、任务清单、引用、代码和链接；预览中的任务复选框直接修改原 Markdown。
- 任务清单属于正文，不增加独立子任务数据模型。
- 输入停止 400ms 后保存；离开编辑页或进入后台时立即刷新待保存内容。只有成功落盘才能显示“已保存到本机”；失败保留编辑内容并允许重试。
- 连续输入期间每隔至多 2 秒安排一次最新快照保存，避免防抖一直不落盘。同一 Todo 的保存串行执行；保存期间继续输入，只能确认已落盘的版本，较旧回执不得清除较新修改的待保存状态。
- 编辑／预览切换保留正文、选区及编辑会话的撤销历史；不通过渲染结果反向重建 Markdown。中文输入法组合期间不因自动保存、标题派生或同步刷新重设输入框内容和 composing 区域。[Flutter 文本编辑说明](https://api.flutter.dev/flutter/widgets/TextEditingController-class.html)
- 预览禁止执行原始 HTML，不自动加载网络图片。本地图片通过系统文件选择器导入，保持桌面端格式、10 MiB 限制和图片占位展示。
- 保存机制不能只依赖退出回调；Flutter 明确说明进程终止时可能收不到生命周期通知。[Flutter 生命周期说明](https://api.flutter.dev/flutter/dart-ui/AppLifecycleState.html)

**分类与回收站**

- 沿用桌面端单目录、多标签及名称校验规则；标签重命名同步更新关联 Todo，包括回收站内容。
- 删除目录时明确提示受影响的子目录和 Todo；删除与恢复遵循桌面端同批次规则，避免恢复此前单独删除的任务。
- 标签软删除保留原始关联，恢复后重新可见；彻底删除才移除 Todo 中的标签名称。
- 回收站固定保留 30 天，到期后在应用启动、恢复前台或后台任务获得执行机会时清理。
- Todo 恢复保留原 ID、目录和标签；原目录尚未恢复时显示在未分类中。桌面位置由桌面端自身的本机状态恢复。
- Todo 彻底删除必须可靠保存墓碑并移除 Markdown 文件，不能将文件缺失直接解释为同步删除。
- 目录／标签自身的删除通过更新 `classification` 对象传播，不发明独立的 `category` 或 `tag` 同步对象；目录删除涉及的 Todo 按各自状态传播。恢复遇到同名冲突时保留回收站条目并显示原因，不覆盖现有分类。

**系统分享**

- 接收其他应用分享的文字或链接，进入预填内容的新建编辑页，并按正常流程自动保存。
- 冷启动、热启动均可处理；同一次分享事件只创建一条 Todo。
- 以分享事件标识处理重投递；正文相同的两次独立分享允许创建两条记录。首次引导和已有编辑会话不得吞掉待处理的分享内容。
- 首版不解析网页正文、不自动下载链接图片、不接收任意附件。

## 4. 数据、接口与同步设计

本地格式遵循 [TaskTips 数据设计](../../tasktips/docs/tasktips-design.md)，HTTP 遵循现有 [OpenAPI 契约](../../tasktips-cloud/contracts/openapi.yaml)。

- Flutter 使用原生 Material 3 页面；分离界面、应用用例、领域规则、本地文件存储和同步适配层。
- Markdown＋front matter 为 Todo 权威数据；分类和索引保持现有 JSON 格式。保留未知 front-matter 字段、稳定 ID、日期语义和版本信息。
- `categoryId` 保存目录 ID，`tags` 保存标签名称；不直接采用演示稿中的 `folder`、`done` 等简化字段。
- 本机主题、设备身份、同步凭据、恢复副本与项目内容分离；Android 不创建或同步桌面窗口状态。
- 从 OpenAPI 生成 Dart HTTP 客户端及传输类型；领域模型通过适配层转换，不另行定义一套服务端接口。
- Android 适配层负责分享接收、文件选择、安全凭据存储和后台调度。

### 4.1 本地持久化与格式兼容

- 使用应用专属持久目录，保持 `content/tips/`、`content/tips/images/`、`content/classification.json`、`content/index.json`、`state/`、`recovery/` 的逻辑分区；Todo ID 使用 ULID，设备 ID 使用安装级 UUID。正式数据不能放在可被系统清理的缓存目录。
- Todo front matter 的 `deviceId` 保留创建设备；同步对象信封的 `deviceId` 标识本次修改设备。`createdAt`、`updatedAt`、`completedAt` 使用 RFC 3339 UTC，完成及取消完成分别设置和清空 `completedAt`。
- 文件写入采用同目录临时文件、刷新、原子替换，并保留最近有效副本。分类级联修改和物理删除使用可恢复的本机操作记录；重启后可以幂等完成未结束的操作。墓碑持久化成功后才允许移除 Todo 文件。
- 内容哈希按实际传输字节计算 SHA-256。下载时先校验原始字节，单纯打开或预览不重新序列化文件；真实编辑保存时才规范化为 UTF-8／LF 并产生新哈希，避免 Dart 与 Rust 的 YAML 排版差异造成虚假冲突。
- 解析失败或不支持的新 schema 保留原件及恢复副本，相关对象只读并提示更新或恢复；单条 Todo 损坏不阻断其他任务。索引可重建任务查询信息，但不能凭现存 Markdown 重建已删除对象的墓碑；墓碑状态不明时暂停该项目自动推送，先从可靠副本或远端核对。
- 对象限额与共享领域和服务端约束核对：当前 Todo payload 为 8 MiB、分类和索引各 5 MiB、图片 10 MiB；按完整序列化字节计算，不按字符数计算。超限保留本地内容并显示原因，禁止截断后上传。
- 图片按文件头校验 PNG／JPEG／GIF／WebP／BMP，拒绝 SVG；使用生成的文件名和 `images/<id>.<ext>` 引用。删除图片引用或 Todo 不自动清理孤儿图片，避免破坏其他引用。

### 4.2 首次连接与同步流程

1. 输入服务端地址、邮箱、密码，登录后注册 Android 设备，选择已有项目或创建项目。
2. 首次连接先读取远端概况，展示本机待合入、远端待接收及冲突情况；用户确认后开始写入同步。
3. 同步 Todo、分类、索引、图片和墓碑；首次 bootstrap，后续使用增量游标，上传内容后提交对象版本。
4. 遵守 revision CAS、generation 和请求幂等规则；本地保存、同步写回和后台任务统一协调，避免覆盖编辑中的新内容。
5. 正文、分类和索引均按整对象处理冲突；提供“保留本机／采用远端”，确认后提交新版本，双方恢复副本继续保留。
6. generation 变化时暂停旧上下文提交，保留本机改动并重新 bootstrap；认证失效、设备撤销、项目维护与断网显示不同处理提示。

首次“合入”指不同对象的收发，不意味着字段级合并。两端都存在且内容不同的 `classification` 或 `index` 对象仍需按冲突处理；确认面板说明采用某一版本对分类或排序的影响。保留双方恢复副本；分类缺失时保留 Todo 原始关联并按未分类展示，索引处理不得丢弃本机已确认的墓碑。预览后本机或远端又发生修改时重新计算，不按过期预览强行覆盖。

### 4.3 同步进度、重试与并发

- 在本机持久化项目 generation、pull cursor、已确认的远端 revision/hash、未完成请求和冲突记录；按规范化服务端地址、账号 ID、项目 ID 隔离。启动后从已确认状态恢复，不将内存中的“已提交”视为完成。
- bootstrap 必须处理完整分页，最终 cursor 在快照完整持久化后启用；pull 的下一 cursor 只能在该页对象、墓碑或完整冲突副本均可靠保存后推进。磁盘写入失败不能跳过该页。
- push 持久化请求 ID 与对应的不可变请求内容；响应丢失时使用同一请求重试，不能把新编辑内容套入旧请求 ID。逐项处理 applied／conflict／rejected，只更新成功对象的基线，不将一批部分成功标记为全部同步完成。
- 保存期间收到远端更新时，先保留本机待保存内容，再比较基线；禁止直接替换正在输入的正文。网络等待不长期占用文件写锁，应用远端内容前重新校验本机版本。
- 手动、前台与后台同步共用项目协调机制，跨 isolate／进程仍只能有一轮同步修改同一项目；Token 刷新也需串行协调，避免轮换凭据被重复使用。
- 用户选择冲突版本时再次验证双方 revision/hash；一方已变化则要求刷新。删除与编辑冲突明确标示“此版本为删除”，图片冲突也保留双方文件；选择删除仍生成墓碑。
- “已保存到本机”与“已同步”分别展示。同步页区分仅本机、待同步、同步中、已同步、部分失败和有冲突；未上传内容、被拒绝对象或未解决冲突存在时不能显示全部完成。
- 网络故障和可重试服务错误使用退避重试并遵守服务端限流；校验失败停止重试该对象，登录失效、设备撤销和项目维护暂停提交并给出对应操作。

### 4.4 调度、凭据与 Android 边界

- 首版同时连接一个账号、一个活动项目。更换账号或项目必须停止旧同步、重新预览确认并隔离同步基线。
- 自动同步开启后，在启动、恢复前台、网络恢复和本地修改保存后触发，并在前台每 60 秒检查。
- 自动同步默认在首次连接确认后开启；关闭后取消自动触发和后台周期任务，本地变更继续保留为待同步，手动同步仍可用。取消任务不能回滚已被服务端接受的对象。
- 后台使用 WorkManager，默认申请 15 分钟周期；界面说明由系统调度，不承诺准点执行。[Android 后台调度说明](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)
- 退出登录保留本地内容；密码不落盘，刷新凭据放入系统安全存储。
- 服务端地址支持 HTTP/HTTPS，不接受含凭据、查询或片段的地址。access token 只放内存；日志同时排除完整请求/响应正文和签名 URL。
- 退出登录或更换连接时停止旧任务并使旧连接的异步回调失效，旧响应不能写入新连接状态。离线退出立即清除本机凭据，并明确远端会话尚未确认撤销。
- 设备身份、刷新凭据、同步基线、未完成请求和本机操作记录排除系统云备份与设备迁移；新安装生成新设备身份并重新登录、bootstrap，不能克隆旧设备的提交上下文。Android 的云备份与设备迁移需分别配置规则。[Android 备份规则](https://developer.android.com/identity/data/autobackup)
- 设备列表展示真实设备数量、名称、平台和最近活动时间，以“一部 Android＋两台桌面设备”验证互通，不限制只能三台。
- 同步日志仅记录时间、方向、数量、结果和错误码，不记录正文、密码、Token 或存储凭据。
- 同步日志是本机实际执行记录；设备列表来自账号设备接口，“最近活动”不能推断为实时在线，也不把账号设备列表当作当前项目的参与设备证明。

权限按需使用：本地待办不要求登录、通知、相机或广泛文件访问权限；图片通过系统选择器授权。后台调度受系统约束，强制停止期间不承诺同步或回收站即时清理，重新打开后恢复检查。

## 5. 交付顺序与验收

按三个阶段推进：

1. **本地闭环**：Flutter 基础工程、主题导航、待办编辑、列表搜索、分类和回收站。
2. **桌面互通**：生成 API 客户端、登录项目连接、同步调度、冲突处理、设备信息和日志。
3. **Android 完善**：分享入口、键盘与返回行为、无障碍、后台恢复和发布检查。

重点验收场景：

- 桌面创建 → 手机编辑 → 桌面接收，正文、标签、目录、图片引用和未知字段保持兼容。
- 今日、过期、未来日期、无日期、完成与取消完成，在跨日和时区变化后结果正确。
- 中文输入、格式编辑、预览勾选、快速返回、存储失败、进程被终止后，已确认保存的数据可恢复。
- 目录整树删除、单独恢复子项、标签恢复、30 天清理和墓碑传播保持一致。
- 三设备离线修改、并发冲突、断网重试、Token 轮换、服务端恢复后重新同步不会静默覆盖内容。
- 分享冷／热启动不重复创建；浅深色、大字体、键盘遮挡及系统返回行为正常。

补充以下可复现的验收用例：

| 场景 | 必须满足的结果 |
|---|---|
| 正在保存旧快照时继续输入并修改日期 | 最终正文和日期都是最新值，旧回执不能将新修改标成已保存。 |
| 同一条 Todo 在手机输入时被桌面修改或删除 | 保留手机输入并进入冲突处理，不重置光标或静默覆盖。 |
| pull 下载成功但本机落盘失败，随后重启 | cursor 未越过失败页，重试后既不漏对象也不错误删除。 |
| push 已被服务端接受但响应丢失 | 重启后重试原请求，不重复提交 revision；新修改使用新请求。 |
| 本机、远端各有分类和排序，首次接入 | 明确呈现整对象冲突及影响，不宣称已自动合并全部分类。 |
| 分类级联、写墓碑或替换 Markdown 中途终止 | 重启后恢复到可解释状态，已确认墓碑不丢失，任务不因索引损坏复活。 |
| 纯读取含未知字段、CRLF、emoji 的桌面文件 | 不产生无编辑上传；真实编辑后格式及派生标题与共享样例一致。 |
| 旧账号同步响应晚于退出登录或新账号连接 | 旧响应被丢弃，内容与同步状态不串用。 |
| 关闭自动同步、离线退出、设备迁移 | 自动任务停止；本机内容保留；新设备不复用旧身份、Token 或待提交请求。 |

兼容性测试使用桌面端序列化与同步样例建立共享夹具，并执行三设备互通测试；仅验证 JSON 能解析不足以证明兼容。UI 检查覆盖 360dp 窄屏、设计稿 390dp、200% 字体和 TalkBack。性能检查使用 release 构建与至少 1000 条 Todo 的数据集，记录冷启动、搜索响应和输入流畅度，避免仅以模拟器 debug 结果判断。

工程建立后运行并记录 `flutter analyze`、`flutter test`、`flutter build apk`；当前尚无 Flutter 工程，不将这些检查标记为已通过。同步更新设计稿和 AGENTS.md，统一为本方案确定的首版行为。

## 6. 开工前仍需确认的事项

以下事项尚未计入已确认功能，不应由实现人员默认扩展范围：

- **本地备份与导出**：明确未连接同步的用户如何迁移数据，以及卸载／清除应用数据后的恢复边界。建议增加通过系统文件选择器导出、恢复完整项目包的能力，但是否进入首版需确认；同步不能替代独立备份。正文是否参与 Android 系统云备份和设备迁移也需明确，不能沿用平台默认配置后仍笼统宣称内容只留本机。第 4.4 节的设备身份与凭据排除规则不受此选择影响。
- **跨账号／项目切换**：当前只确认一个账号、一个活动项目及首次接入合入。还需选择“切换为另一份独立数据”或“将当前本地内容迁入目标项目”；两者不能使用同一个含糊的“切换”按钮。未确定前只实现首次绑定及同一目标重连，不提供自动上传原项目内容的一键切换。
- **Android 支持与发布基线**：锁定最低 Android 版本、Flutter／Dart 版本、核心依赖、发布 applicationId 和签名策略；以所选工具链与插件共同支持的范围为准。另需同步 AGENTS.md 中仍为 v0.2 的说明，并补齐设计稿尚未表达的冲突、三类回收站和同步状态布局。
